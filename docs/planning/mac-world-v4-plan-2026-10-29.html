mac-world v4 plan: the strongest contention window controller we can defend

How to continue the project from the v3.4.0 state so that the final method beats OSCAR, BEB and the strongest heuristic and learned baselines on every arena where beating them is physically possible, and matches the static optimum where it is not.

Based on: dev branch 17c0615, results v3.1.0 to v3.4.0, the 27 Oct research note, the 29 Oct Contention Window Atlas, the OSCAR metrics noteRevision 2 (29 Oct, after review): statistics, budget and method fixes; decisions takenNo new runs were made for this plan

Bottom line

  1. In one collision domain there is a hard ceiling, and the project has already reached it. At 20,40 the best static common CW (512) gives 39.62 ± 0.21 Mbps, and a frozen shared agent gave 39.74 Mbps on one seed fact. No method, learned or not, can beat the best static CW there by much, because aggregate throughput depends mainly on the total attempt rate lit. "Beat every method" on aggregate there means reach the ceiling reliably, fast, and without per-scenario tuning.
  2. The real wins are in four arenas where one fixed CW cannot be optimal: asymmetric topologies (hidden or partial overlap, uneven load), changing conditions (load and active-station changes), tail latency at non-saturated load, and generalisation to unseen network sizes. v3.4.0 already shows the first one works: independent agents with a proportional-fair reward beat BEB and Global-CW on PF utility and the weakest AP in all 8 seeds fact.
  3. Proposed method, working name RAFA (Residual α-Fair Agents): one parameter-shared TD3 actor per AP, fed by channel-sensing observations, acting as a bounded residual on top of an analytical CW prior (IdleSense or Bianchi), trained on an α-fair team reward with α as a policy input, a no-harm constraint against BEB, and domain-randomised scenarios. Each part fixes a specific failure seen in the repo or the literature.
  4. Baselines must grow from 3 to about 12, most of them cheap non-learning rules: static oracle, IdleSense, Bianchi/Kalman, Patras PI, Gawłowicz PF gradient search, BLADE-style HIMD, a per-AP UCB bandit, plus OSCAR (global and per AP), CCOD and a drlCW re-implementation. Kosek-Szott et al. 2021 showed a tuned heuristic can match DRL lit, so this is what reviewers will check first.
  5. Compute is the binding constraint. One 15 s job takes about 430 to 880 s and jobs run one at a time because parallel runs failed fact, probably because lanes with the same seed pick the same port inference. Counted properly, the suite is about 260 serial hours inference. The plan cuts that with a two-stage evaluation, parallel lanes and a cheaper saturated load, and has a fixed order of what to drop if those fall short.

Three facts shape the plan. First, frozen policies behave like a fixed per-AP CW choice in these static scenarios (CI ± 0 on the last-100 CW, v3.4.0 §4), so RL adds value over a static oracle only when conditions change or the oracle is unknown. Second, the shared actor gives every AP nearly the same CW because every AP sees nearly the same loss observation; it cannot tell the middle AP from an edge AP. Third, no arm sits on the Pareto front in the hidden chain yet: Global wins aggregate, the oracle wins fairness, and the front between them has not been mapped (the static grid was 3 × 3 with equal edges).

What "beat every existing method" can mean

Defined up front so the claim is testable and survives review. The plan targets all five arenas and pre-registers the win rule for each (see Win criteria).

A1 · ONE DOMAIN

Reach the ceiling

Within 2 % of the per-scenario static oracle, with one policy for all sizes and no tuning. Beats BEB and per-AP OSCAR clearly; ties are the honest best against a tuned heuristic.

A2 · ASYMMETRIC

Own the Pareto front

Hidden pairs, partial overlap, uneven load. No baseline dominates RAFA on (aggregate, min-AP), and RAFA beats each baseline on the α-fair utility it was asked for.

A3 · DYNAMIC

Adapt faster

Load steps and stations going active or idle. Lower regret against a per-phase oracle and faster re-convergence than OSCAR, drlCW and the feedback controllers.

A4 · LATENCY

Cut the tail

Non-saturated load. Lower p95 and p99 delay than BEB and BLADE-style control without losing throughput. BLADE and drlCW show this is where per-AP control wins most clearly lit.

A5 · UNSEEN

Generalise

Trained on small topologies, tested on larger or new ones. Keep 95 % of the oracle where per-scenario learners must retrain.

The proposed method: RAFA

A redesign of the agent, not of the simulator. The ns-3 scenario, ns3-gym stepping, and per-AP CW control stay as they are; everything new is opt-in so the old results remain reproducible byte for byte.

Every component enters through an ablation. A component stays only if it improves the primary metric on the gate scenarios S4 and S5 (paired, n=10) or is neutral and needed by another one. The prior alone (Δ = 0) is reported as its own baseline, so if it matches RAFA in a scenario the write-up says so. The main method is the local-only RAFA (C5 off). RAFA-N, with the neighbour summary, is reported as a variant and becomes the main method only if it beats RAFA by more than the CI on A2.

Baselines

All run inside mac-world on the same seeds, so every comparison is paired. Heuristics designed per station are run at AP level (the AP sets its BSS's CW every control step, as OSCAR does) and labelled "AP-level adaptation". Most need no training, which keeps them cheap. Every baseline gets the same small tuning budget as RAFA: 3 to 4 settings of its main parameter (IdleSense target, PI gains, KW step size, BLADE rate constants, UCB exploration) on selection seeds 0 to 2 of S2 and S4, never on evaluation seeds.

  • Seeds decision: selection seeds 0 to 2 for tuning and oracle choice; held-out evaluation seeds 101 to 110 (n=10) for every reported number; training seeds separate from both. Train, save, then evaluate frozen with no noise, every method on the same evaluation seeds.
  • Two-stage evaluation decision: Stage 1 runs every method on 5 of the 10 evaluation seeds and ranks the baselines per scenario (reported in full, no significance claimed). Stage 2 adds the other 5 seeds for RAFA, BEB, OSCAR per AP and the top 3 other baselines (Global-CW OSCAR is in Stage 2 if it ranks in the top 3), so every claim is RAFA against at most 5 baselines at n=10. Stage-1 runs are reused, so nothing is run twice.
  • Training seeds: 3 for RAFA and for the strongest learned baseline, 1 for the other learned baselines. A claim also needs all 3 RAFA seeds to beat the baseline on their own (sign consistency), because 3 policies are too few for a policy-level test.
  • Tests: exact Wilcoxon signed-rank and paired t-CI, Holm correction across the at most 5 baselines in each table (n=10 makes p = 0.002 reachable). "Matches the oracle" is an equivalence test (TOST) with a ±2 % margin, so a tie is a stated result rather than a missing one.
  • Report: a wins / ties / losses grid of RAFA against every baseline on every scenario and metric, plus Pareto plots (aggregate against min-AP) for S4 to S6.

Phases

Ordered by dependency. Filled markers are core; dashed markers are optional. Versions continue the repo's numbering; v3.3.0 is the open sensing-and-heuristics milestone and is absorbed here.

P0 · Foundations

v3.5.0 · effort M · ~4 h compute
  • Fix parallel ns-3 jobs. wrappers.py picks the ns3-gym port as 13968 + np.random.randint(40000), and the trainer calls np.random.seed(args.seed) before that fact. Two lanes with the same --seed (as in the v3.1.0 sweep) therefore get the same port, which is the most likely cause inference; concurrent ./waf --run calls are the second suspect. Draw the port from an unseeded source or a lane index, run the binary directly, and prove 4 parallel jobs give traces identical to serial ones.
  • Add opt-in traces to cw.cc (project code, no upstream change): PHY State intervals for idle slots and busy fraction, Retry-bit counts on received data frames, MacTxDataFailed per AP, FlowMonitor delay histograms per AP. Export them through extraInfo.
  • Add a per-STA application on/off schedule for S8.
  • Extend summarize_run.py and aggregate_bench.py with U_α, oracle gap, convergence time, delay percentiles and Holm-corrected tables.
  • Speed test: time BEB and two static CWs at 150 Mbps against 10 Mbps per STA on S2 and S4 (both far above capacity, so still saturated). If the results match within the CI and the job is clearly faster, the new suite uses the lower load and old results stay as they are inference: the 150 Mbps sources generate many packets that are only dropped.
  • Measure physical cores and set lanes = cores − 1.
  • Optional, small: --trainSeed 2 for the two v3.4.0 PF arms to close that milestone's open item.

Exit: regressions unchanged (dry 10533, 5,15 = 9000, smoke 10.59458, default traces byte-identical); new metrics sane on 2,3 and 10,10,10; idle-slot mean falls as CW falls; parallel lanes validated; load decision recorded. Timebox: 1 week of work.

P1a · Oracle, priors and the feature gate

v3.6.0 · effort M · ~25 h compute
  • Fine static sweeps on S2, S4, S5 and each S8 phase (per-AP grid plus local search, selection seeds 0 to 2) for each scenario's oracle and the static Pareto front.
  • Implement IdleSense and Bianchi/Kalman (both are RAFA priors). Sanity tests: IdleSense reaches its idle-slot target; the Kalman estimate of n tracks the real station count.

Gate G0: on the static grids, the C1 features at the oracle CW are near-constant across scenarios (for example idle slots at the oracle within ±20 % of one target). If not, rethink C1 and C2 before any RL run. Gate G1: if a prior is within 2 % of the oracle on S2, the A1 claim becomes "RAFA ties the best heuristic" and effort moves to A2 to A5.

P1b · Remaining baselines, coded while P3 runs

v3.7.0 · effort M · compute counted in P4

Decisions taken

You left these to me. Each is recorded here and in the repo, and can be reversed.

  1. Claim framing: the five arenas. In one collision domain the static optimum is a hard ceiling, so an aggregate-only claim could not be won by much. The oracle is a reference to reach, not a baseline to beat.
  2. Scope: per-STA traffic on/off schedules, yes. S8 needs them, and they avoid the out-of-scope dynamic-association code. An ADR is written before the code.
  3. Scope: neighbour summaries, as a variant only. RAFA-N is built and reported, but the main method stays local-only, which keeps the per-AP observation isolation of ADR-0002. RAFA-N becomes the main method only if it wins A2 by more than the CI. It gets its own ADR.
  4. Compute: current machine first. Fix the lanes, set lanes from measured cores, test the cheaper load, and use the two-stage evaluation and the trim order. No new hardware is assumed.
  5. Re-implemented baselines: yes. drlCW and BLADE are labelled "re-implemented from the paper", and their code is in the repo. BLADE is dropped, with the reason stated, if its rule cannot be pinned down from the paper.
