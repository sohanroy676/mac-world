Bottom line

  1. Every existing method fails somewhere. At 30 s and n = 10 (α = 1): Global-CW (OSCAR) is near the ceiling in one domain (S2 GC 0.97) and with uneven load (S5a 0.94), but only 0.33 in the flow-in-the-middle chain (S4). IdleSense starves an AP in S4 and S5a. KW is strong in S2 and S4 (0.90, 0.92) but misses the S4 fair floor and drops to 0.72 in S5a. CCOD is feasible everywhere but only 0.54 in S4. The per-scenario PF learner reaches 0.95 in S4 but only 0.43 to 0.74 in S2 fact, M2 doc.
  2. So the contribution is robustness: one controller with no weak cell. The primary claim (Claim 1) is minimax: RAFA beats every rival in that rival's weakest cell and has a higher worst-cell GC than every rival. Today the best worst-cell score among feasible rivals is CCOD's 0.54 fact. The secondary claim (Claim 2) is the harder one: RAFA within 0.05 GC of the best specialist in every cell.
  3. The bar in each cell is now known. In S4 at α = 1, the best feasible rival is the per-scenario PF learner at 0.95 and the best general method is UCB at 0.66. In S2 it is Global at 0.97. In S4 at α = 0 it is CCOD at 1.14 fact. RAFA must reach these with one policy trained once.
  4. RAFA is kept, with five corrections from the M1 and M2 evidence. Idle slots carry the role signal, while the Retry rate does not (gate G0b failed on Retry fact). The loss input is dropped. The floor penalty weight is fixed instead of being an input. S2, where learners have failed before, is now tested in step 1. Training runs at the evaluation load.
  5. Four rivals get stronger before any claim is tested, so a win cannot come from a weak baseline. Global and the PF learner are retrained with 12 episodes (as CCOD had) and 3 seeds, and CCOD gets 3 seeds. drlCW (the closest prior work; the mentor supplied its paper) and the Patras PI controller (its text is now read) are built. Claims are tested against each rival's strongest seed.
  6. Compute. The machine has 3 cores, so 2 lanes fact. The core path is about 305 serial hours, about 153 h wall-clock (about 6.5 days of running). The extended tier adds about 91 h serial. You said time is not a constraint (7 Nov), so the whole plan runs. Gates come first, so a failed idea costs hours, not days.

The claims and how they are scored

CELLS

13 core cells

S2, S4 and S5a, each at α = 0, α = 1 and max-min; S7 (two delay configurations); S8 (three-phase dynamic) at α = 1 and max-min. α = 2 is still reported, but is secondary (issue 5).

METRIC

Gap closed (GC)

GC = (U − U_BEB)/(U_oracle − U_BEB). U_α = Σ n_i·u_α(max(ε, x_i/n_i)) with ε = 0.01 Mbps per STA. The max-min cells use U = min_i x_i/n_i. Delay cells use GC_D on log p99. n_i counts active stations.

CLAIM 1 (primary)

No weak cell

For every rival: in that rival's weakest cell, RAFA is significantly better (one-sided paired t, Holm over rivals), and RAFA's worst-cell GC is above the rival's. Both RAFA ensembles must pass.

CLAIM 2 (secondary)

Near the best specialist

In every conclusive core cell, RAFA is at most 0.05 GC below the best feasible rival (intersection-union test, each cell at 0.05). This is reported whether it passes or not.

RuleDefinition, fixed now
Fair floorfloor_i = min(BEB_i, BEB aggregate · n_i/Σn), from the same seeds' BEB runs. A method is infeasible in a cell if any AP's mean over the evaluation seeds is below 0.95 · floor_i. The 5 % slack was set after M0 showed the S4 oracle 2.9 % short, so it is post hoc fact. Sensitivity at 0 % and 10 % is reported for every claim, and a conclusion that changes with the threshold is stated as threshold-dependent.
OracleThe best floor-feasible static setting on selection seeds, from the octave grid (STAs under a static setting use 2^k − 1 after the first beacon fact, readback logs). Adaptive methods can exceed it (GC > 1).
SeedsSelection: python 0 to 2. Stage 1: 100 to 102, used only to pick each cell's best rival, each rival's strongest training seed and each rival's weakest cell. Confirmation: 103 to 109 (n = 7), the only seeds used in the claim tests. Training: ns-3 2001 and up.
PowerFrom Stage 1, estimate the paired SD per cell. If n = 7 gives under 80 % power at a true tie (Claim 2) or at a 0.1 GC gain (Claim 1), extend that cell to seeds 103 to 119 (n = 17). A cell still under 80 % is inconclusive: it is reported but cannot count as a pass.
Degenerate cellsIf U_oracle − U_BEB is below 3 BEB seed SDs, the cell is scored on raw U with a 1 % margin. It is not used for the worst-cell headline.
Infeasible rivalsA rival counts as beaten in its weakest cell by infeasibility only if RAFA is feasible there and the rival's shortfall below 0.95 · floor is significant on the confirmation seeds (one-sided t).
Multi-seed rivalsEach multi-seed rival is represented by its strongest training seed, picked on Stage 1. RAFA is represented by each ensemble separately.
TestsPaired t on per-seed differences. The exact Wilcoxon is shown unadjusted, as a descriptive check only (its smallest p at n = 7 is 1/64). An analysis spec with code, cells, seeds and margins is committed before any RAFA evaluation run (pre-registration by git timestamp).
S8 referencesPer-phase BEB and per-phase best feasible static (a switching oracle), summed over the phases. A best-single-static reference is shown as well.

M3 · RAFA

v4.0.0 · ~86 h compute
  1. Step 0, checks (about 3 h).
    • CW granularity: a 2,3 learner run with --cwReadbackEvery 0.01 counts STA time at the exact CW against the rounded 2^k − 1 value.
    • Determinism: a same-seed learner rerun with cmp on the trace.
    • The pool's equal-load BEB references rerun at 10 Mbps.
    • Input scales written into ADR-0007.
  2. Step 1, shared actor on S4, S5a and S2 (new observation, station-weighted PF reward, α = 1, 6 episodes, 3 seeds; about 11 h).
    • Gate G1 (S4): the edge/middle CW ratio is at least 2 in at least 2 of 3 seeds (the oracle is 128,64,128).
    • Gate G2 (S2): GC is at least 0.86 (IdleSense − 0.05) in at least 2 of 3 seeds.
    • Gumbel test on S4 and S2 (about 13 h): --noiseDist gaussian | gumbel | gumbel-raw. gumbel is centred and has the same SD; the same training seeds are used, so torch initialisation matches. Adopt Gumbel only if it is ahead on every seed pair in both cells and the mean gain is at least max(0.05, one Gaussian seed SD).
  3. Step 2 (about 32 h): add the α input with relabelling and the fair-floor penalty.
    • Pick λ from {1, 3, 10} at 6 episodes: the highest mean α-1 GC over S4 and S5a among values feasible in both.
    • Then 12 episodes for that λ. Keep 12 only if it gains at least 0.05 GC.
  4. Step 3 (about 13 h): the scenario pool, 24 episodes round-robin, 3 seeds. Gate G3: pooled RAFA is within 0.05 GC of the step-2 per-scenario RAFA on S2, S4 and S5a. Then 6 final seeds (about 14 h) form the two ensembles.

Kill rules: if G1 fails, use independent actors for fixed topologies and keep the shared actor only for unseen scenarios. If G2 fails, try one input change: add the AP's own idle-slot target error, as IdleSense uses. If it still fails, S2 is reported as RAFA's weak cell, which the claim allows to be lost. If G3 fails, RAFA is reported as per-scenario, and Claim 1 is tested on that basis.

Decisions taken

  • The primary claim is minimax robustness (Claim 1). Near-best-everywhere is secondary (Claim 2).
  • Max-min cells replace α = 2 as primary, because α = 2 is dominated by ε when an AP nearly starves (S4 α = 2 is degenerate). This needs analysis only; no runs.
  • Claim tests use confirmation seeds only. Selection uses Stage 1 seeds.
  • Rivals are strengthened before testing: equal episode budget for the main learners, 3 seeds, strongest seed in the claims.
  • drlCW, Patras DAC and the model-based static are built. Bianchi/Kalman is replaced. BLADE waits for its appendices.
  • RAFA inputs: idle, Retry, goodput per STA, active STAs and CW exponent. λ is fixed. Training uses the evaluation load. Gumbel is tested, not assumed.
  • Time is not a constraint (your instruction, 7 Nov): the full core and extended tiers run.
