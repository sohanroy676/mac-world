# Benchmark: Hugging Face Space (Gradio SDK, ZeroGPU hardware, Python 3.7 set in README) (2026-11-10)

Run via `tools/bench/hf/app.py` (no-root, `--no-apt`, `-Wno-error`), branch bench/hf. Cell: 20,40 APs, beb, seed 0, simTime 15, 1500 steps.

| Item | Value |
|---|---|
| Hardware seen | Xeon Platinum 8559C host (192 threads, 2 TB RAM), nproc 16 inside the Space; real share unknown |
| OS / toolchain | Debian 12, GCC 12.2.0, protoc 3.21.12, libzmq 4.3.4, Python 3.7.12 (micromamba), torch 1.13.1+cpu |
| Clean ns-3 build + dry run | 117 s |
| Single cell | 553 s (9.2 min), --check PASS |
| 2 seeds at once | 550 s and 557 s each, phase 560 s, both exit 0 |
| Throughput | single 6.5 cells/h; 2 at once 12.9 cells/h |

Findings: default Python 3.14 / GCC 14 (Debian 13) failed (waf needs `imp`); Python 3.7 in README gave Debian 12. ZeroGPU Spaces need a @spaces.GPU function to start. Needed -Wno-error for GCC 12. Not yet known: Space sleep/restart behaviour on long runs, cores actually guaranteed, persistence of results (none; disk is ephemeral), whether CPU-only use of ZeroGPU hardware is allowed long-term.
